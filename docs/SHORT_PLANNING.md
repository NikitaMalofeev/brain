# Краткосрочный план разработки Yoga Mini App

## Логические основания проекта
- **Вещи**: Telegram Mini App для йоги и медитаций с системой квиза для подбора практик
- **Свойства**: Интерактивность, персонализация, доступность, интеграция с Telegram
- **Отношения**: Пользователь ↔ Практики, Выбор пользователя ↔ Рекомендации, Телеграм ↔ Приложение

## Логические основания
- **Контекст**: Быстрый roadmap и чеклисты для текущей итерации/релиза
- **Цель**: 100% покрытие квиза, realtime, dev/prod стабильность, чистый деплой, UX админки, MCP диагностика
- **Критерии успеха**: билд без ошибок, нет "пустых" веток квиза, realtime работает, MCP тесты проходят, админка покрывает все CRUD, smoke-тесты зелёные

## Детальный план для каждого этапа

### Структура базы данных

1. **Таблица quiz_logic**
   - `id` (UUID, PK)
   - `practice_type` (string) - тип практики: 'physical', 'breathing', 'meditation', 'short'
   - `duration_min` (integer) - минимальная длительность в секундах
   - `duration_max` (integer) - максимальная длительность в секундах
   - `goal` (string) - цель практики, например 'relax', 'energize', etc.
   - `approach` (string) - для медитаций: 'self', 'guided'
   - `content_id` (UUID, FK) - ссылка на таблицу contents
   - `priority` (integer) - приоритет для выбора
   - `created_at`, `updated_at` (timestamptz)

2. **Таблица contents**
   - `id` (UUID, PK)
   - `title` (string)
   - `subtitle` (string)
   - `description` (text)
   - `duration` (integer) - длительность в секундах
   - `thumbnail_url` (string)
   - `background_image_url` (string)
   - `content_type_id` (UUID, FK)
   - `category_id` (UUID, FK)
   - `difficulty_level` (string)
   - `kinescope_id` (string) - для видео
   - `audio_file_path` (string) - для аудио
   - `is_premium` (boolean)
   - `is_featured` (boolean)
   - `display_order` (integer)
   - `metadata` (jsonb)
   - `created_at`, `updated_at` (timestamptz)

3. **Таблица user_quiz_history**
   - `id` (UUID, PK)
   - `user_id` (UUID, FK)
   - `practice_type` (string)
   - `duration` (integer)
   - `goal` (string)
   - `approach` (string)
   - `content_id` (UUID, FK)
   - `completed` (boolean)
   - `created_at` (timestamptz)

### Интерфейс квиза

1. **Компоненты пошагового интерфейса**
   - QuizStart.tsx - начальный экран
   - QuizTypeSelection.tsx - выбор типа практики
   - QuizTimeSelection.tsx - выбор времени
   - QuizGoalSelection.tsx - выбор цели
   - QuizApproachSelection.tsx - выбор подхода (для медитаций)
   - QuizObjectSelection.tsx - выбор объекта (для самостоятельных медитаций)
   - QuizResult.tsx - результат и переход к практике

2. **Контекст для квиза**
   - QuizContext.tsx - хранение состояния квиза
   - useQuizState.ts - хук для работы с состоянием
   - useQuizNavigation.ts - хук для навигации
   - useQuizResults.ts - хук для получения результатов

### Логика квиза

1. **Хуки для работы с данными**
   - useQuizOptions.ts - получение доступных опций для каждого шага
   - useQuizLogic.ts - логика фильтрации практик
   - useQuizHistory.ts - работа с историей выборов

2. **Функции фильтрации**
   - filterByType.ts - фильтрация по типу практики
   - filterByTime.ts - фильтрация по времени
   - filterByGoal.ts - фильтрация по цели
   - getRandomPractice.ts - выбор случайной практики из подходящих

### Система плееров

1. **Компоненты плееров**
   - VideoPlayer.tsx - для телесных и дыхательных практик
   - AudioPlayer.tsx - для медитаций с сопровождением
   - MeditationTimer.tsx - таймер для самостоятельных практик

2. **Контекст для плееров**
   - PlayerContext.tsx - управление состоянием плееров
   - usePlayerControls.ts - управление воспроизведением
   - usePlayerSettings.ts - настройки плеера

### Админ-панель

1. **Компоненты админки**
   - AdminLogin.tsx - форма входа
   - PracticesManagement.tsx - управление практиками
   - QuizLogicEditor.tsx - редактирование логики квиза
   - UserStats.tsx - просмотр статистики

2. **Хуки для админки**
   - useAdminAuth.ts - проверка прав доступа
   - usePracticesManagement.ts - управление практиками
   - useQuizLogicManagement.ts - управление логикой квиза

## 4. Новые best practices и хаки

- MCP всегда использовать для диагностики и миграций
- Для realtime — debounce/throttle, фильтрация дубликатов
- Для квиза — не допускать "пустых" веток, использовать генератор комбинаций
- Для админки — защищать route, логировать все действия
- Для деплоя — всегда smoke-тест, сверка env, MCP endpoints
