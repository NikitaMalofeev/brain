# 📝 CHANGELOG - Brain Programming

Хронологический список изменений и обновлений проекта.

## [2.2.0] - 2025-06-30 🛡️ ГИБКИЙ ДОСТУП: ТАРИФЫ И ЧАТЫ

### ✨ Добавлено
- **Ограничение доступа к урокам по лимитам тарифа**: Реализована логика, ограничивающая доступ к урокам внутри ступени на основе поля `max_days_access` в таблице `tariff_limits`. Теперь урок доступен, только если наступило время его открытия (`open_at`) **И** количество уже открытых уроков меньше лимита тарифа. Это обеспечивает более гранулированный контроль над выдачей контента.
- **Привязка чатов к курсам**: Обновлена логика доступа к чатам. Теперь чаты можно привязывать не только к тарифам, но и к конкретным курсам. Пользователь получает доступ к чату, только если удовлетворяет **всем** условиям (и по тарифу, и по курсу). Для инкапсуляции этой сложной логики на бэкенде была создана новая RPC-функция `get_available_chats_for_user`.

### 🎯 Улучшено
- **Рефакторинг страницы чатов**: Страница `Chats.tsx` была переписана для использования новой RPC-функции `get_available_chats_for_user`, что значительно упростило логику на стороне клиента и повысило ее надежность.

### 🚀 Рефакторинг
- **Частичная декомпозиция AdminPage**: В рамках рефакторинга массивного файла `AdminPage.tsx` был вынесен компонент `BlocksManager` в отдельный модуль (`src/pages/AdminPage/components/BlocksManager/`). Это первый шаг к улучшению читаемости и поддерживаемости админ-панели.

## [1.9.2] - 2025-06-19 🔧 КРИТИЧЕСКОЕ ИСПРАВЛЕНИЕ ТАРИФНОЙ СИСТЕМЫ

### 🐛 Исправлено
- **Критическая ошибка доступа к ступеням с NULL лимитами** - исправлена логика функции `can_user_access_stage`
  - Проблема: ступени с пустыми значениями "макс дней/уроков" (NULL) не открывались для пользователей
  - Корень проблемы: функция блокировала доступ тарифов без записей в `tariff_limits` (например, T3, T4)
  - Неправильная логика: "есть правила для ступени, но не для этого тарифа" = блокировка доступа
  - Правильная логика: отсутствие записи для тарифа = безлимитный доступ
  - Результат: высокоуровневые тарифы (T3, T4) теперь получают неограниченный доступ ко всем ступеням

### 🎯 Улучшено
- **Тарифная система** - правильная обработка иерархии тарифов
  - T1, T2 тарифы: ограничены explicit правилами в `tariff_limits`
  - T3, T4 тарифы: безлимитный доступ (нет ограничений)
  - NULL значения `max_days_access`: корректно интерпретируются как "безлимитно"
  - Строгая проверка prerequisites: требование выполнения всех ДЗ работает корректно

### 📝 Техническая реализация
- **Функция `can_user_access_stage`** - исправлена основная логика:
  ```sql
  -- БЫЛО (неправильно):
  IF v_limit IS NULL THEN
      IF EXISTS(SELECT 1 FROM tariff_limits WHERE stage_id = p_stage_id) THEN
          RETURN FALSE; -- Блокировка при наличии правил для других тарифов
      END IF;
  END IF;
  
  -- СТАЛО (правильно):
  IF v_limit IS NULL THEN
      RETURN TRUE; -- Отсутствие записи = безлимитный доступ
  END IF;
  ```
