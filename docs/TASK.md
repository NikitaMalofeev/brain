#### 🚨 **КРИТИЧЕСКАЯ ПРОБЛЕМА:** Ошибка аутентификации при вызове promote_user_to_curator

**Обнаружено:** При попытке назначить пользователя куратором возникает ошибка `'Unauthorized: User not authenticated'`.

**Причина:** 
- SQL-функция `promote_user_to_curator` использует `auth.uid()` для получения ID текущего пользователя
- Админка использует собственную систему аутентификации через `authenticate_web_user`, которая возвращает JWT токен
- JWT токен устанавливается в Supabase сессию через `supabase.auth.setSession()`, НО:
  - ✅ Токен не сохранялся в localStorage (ИСПРАВЛЕНО)
  - ❌ JWT токен может не содержать правильный `sub` claim или не распознаваться функцией `auth.uid()`

**Решения (требует выбора):**
1. **Вариант A (Рекомендуется):** Изменить функцию `promote_user_to_curator` - передавать ID админа как параметр
   - Добавить параметр `p_admin_id UUID` в функцию
   - Проверять роль админа через прямой запрос к таблице `users`

#### План исправления (после выбора варианта):
1. 🟢 **Обновить SQL-функцию** (если выбран Вариант A)
2. 🟢 **Обновить вызов в хуке `useCuratorsAdmin`**
3. 🟢 **Протестировать исправление**

   - 🟢 ✅ Создать тестовую SQL-функцию для проверки `auth.uid()` и JWT claims
   - 🟢 ✅ Добавить временную кнопку "Debug JWT" в карточку студента
   - 🟢 ✅ Обновить функцию `promote_user_to_curator` для поддержки обоих методов аутентификации

**РЕЗУЛЬТАТ ДИАГНОСТИКИ:**

- **Причина:** Supabase client использует anon/service role key для RPC вызовов, игнорируя установленную сессию
