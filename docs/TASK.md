## 🔥 **[КРИТИЧЕСКАЯ]** Исправление подключения к базе данных в админке
**Дата:** 19.06.2025  
**Статус:** 🟢 РЕШЕНО

**ПРОБЛЕМА:** После применения скрипта `enable_extensions.sql` ошибка `function crypt(text, text) does not exist` все еще возникает при вызове RPC `authenticate_web_user`.

**ФИНАЛЬНЫЙ ДИАГНОЗ:**
1.  ✅ **Функция `authenticate_web_user`** находится в схеме `public`.
2.  ✅ **Расширение `pgcrypto`** (с функцией `crypt`) находится в схеме `extensions`.
3.  ❌ **ПРОБЛЕМА:** Функция `authenticate_web_user` объявлена с `SECURITY DEFINER`, что сбрасывает `search_path` во время ее выполнения. Из-за этого она не может "увидеть" функцию `crypt` в схеме `extensions`.

**РЕШЕНИЕ:**
- 🟢 **Модифицировать функцию:** Явно указать схему для функции `crypt`. Заменить вызов `crypt(password_param, ...)` на `extensions.crypt(password_param, ...)` внутри функции `authenticate_web_user`.

**SQL КОМАНДА ДЛЯ ИСПРАВЛЕНИЯ (для выполнения в SQL Editor):**
```sql
-- Пересоздаем функцию с явным указанием схемы для crypt()
CREATE OR REPLACE FUNCTION public.authenticate_web_user(login_param text, password_param text)
 RETURNS TABLE(user_id uuid, user_role text, first_name text, last_name text, is_authenticated boolean)
 LANGUAGE plpgsql
 SECURITY DEFINER
AS $function$
DECLARE
    user_record RECORD;
BEGIN
    -- Ищем пользователя по веб-логину
    SELECT 
        u.id,
        u.role::TEXT,
        u.first_name,
        u.last_name,
        u.web_password_hash
    INTO user_record
    FROM public.users u
    WHERE u.web_login = login_param 
      AND u.role IN ('admin', 'curator')
      AND u.web_password_hash IS NOT NULL;

    -- Если пользователь найден, проверяем пароль
    IF FOUND THEN
        -- Проверяем пароль с помощью extensions.crypt
        IF user_record.web_password_hash = extensions.crypt(password_param, user_record.web_password_hash) THEN
            -- Обновляем время последнего входа
            UPDATE public.users 
            SET web_last_login = now() 
            WHERE id = user_record.id;

            -- Возвращаем успешную авторизацию
            RETURN QUERY
            SELECT 
                user_record.id,
                user_record.role,
                user_record.first_name,
                user_record.last_name,
                true as is_authenticated;
        ELSE
            -- Неверный пароль
            RETURN QUERY SELECT NULL::UUID, NULL::TEXT, NULL::TEXT, NULL::TEXT, false as is_authenticated;
        END IF;
    ELSE
        -- Пользователь не найден
        RETURN QUERY SELECT NULL::UUID, NULL::TEXT, NULL::TEXT, NULL::TEXT, false as is_authenticated;
    END IF;
END;
$function$;
```
**ПРИОРИТЕТ:** Критический - блокирует работу админки.

     - Внутри функции, после определения всех ступеней для пользователя, найти *последнюю разблокированную* ступень (`currentStage`) и *первую заблокированную* ступень (`nextLockedStage`).
