## 🚀 **[Новая функция]** Ограничение доступа к урокам на основе тарифных лимитов (30.06.2025)

**Цель:** Добавить логику, которая ограничивает доступ к урокам внутри ступени на основе поля `max_days_access` в таблице `tariff_limits`. Если у тарифа есть ограничение по количеству уроков, то уроки не должны открываться, даже если наступило время их открытия (`open_at`).

**Бизнес-логика:**
- Поле `max_days_access` интерпретируется как максимальное количество уроков, которые могут быть открыты в рамках ступени
- Урок доступен если: (`open_at` <= NOW) **И** (количество открытых уроков < `max_days_access`)
- При апгрейде тарифа уроки открываются сразу (если их `open_at` уже наступило)
- UI не требует изменений - заблокированные уроки показываются стандартно

- 🟢 **Обновить хук `useStageDetails`:**
  - 🟢 Добавить получение активного тарифа пользователя через `user_tariffs`
  - 🟢 Добавить запрос к `tariff_limits` для получения `max_days_access` для текущей ступени
  - 🟢 Передавать полученное ограничение в логику обработки уроков

### **Этап 2: Реализация логики ограничения доступа**
- 🟢 **Добавить функцию проверки доступности урока:**
  - 🟢 Создать функцию `isLessonAccessible` которая принимает: урок, его индекс, массив всех уроков, лимит тарифа
  - 🟢 Функция должна сначала проверять `open_at` (временное ограничение)
  - 🟢 Затем проверять количество уже открытых уроков до текущего
  - 🟢 Возвращать `false` если превышен лимит тарифа

### **Этап 3: Тестирование**

**Бизнес-логика:**
