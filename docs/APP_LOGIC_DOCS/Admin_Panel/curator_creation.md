# Реализация: Создание аккаунта куратора

## 1. Назначение

Этот документ описывает процесс создания нового пользователя с ролью "куратор" в системе Brain Programming. Цель — предоставить администраторам простой и безопасный способ добавления новых членов команды, которые смогут проверять домашние задания и взаимодействовать со студентами через админ-панель.

## 2. Пользовательский флоу (Admin Flow)

Процесс полностью инкапсулирован в админ-панели и выполняется пользователем с ролью `admin`.

1.  **Навигация:** Администратор переходит в раздел **"Кураторы"** (`/admin/curators`). Этот раздел уже существует для назначения учеников, и мы добавим в него функционал создания.
2.  **Инициирование:** На странице списка кураторов будет добавлена кнопка **"Добавить куратора"**.
3.  **Ввод данных:** При нажатии на кнопку открывается модальное окно с формой, содержащей следующие поля:
    *   `Имя` (first_name) - (Опционально)
    *   `Фамилия` (last_name) - (Опционально)
    *   `Логин для входа` (web_login) - (Обязательно, уникальный)
    *   `Пароль` (web_password) - (Обязательно)
4.  **Сохранение:** Администратор нажимает кнопку "Сохранить". Система выполняет валидацию данных (например, на уникальность логина) и создает нового пользователя.

### 2.1. Требования к паролю
Для обеспечения базового уровня безопасности, пароль должен соответствовать следующим критериям:
*   Минимум **8 символов**

Проверка должна быть реализована на стороне фронтенда с выводом подсказок для администратора.

## 3. Техническая реализация (Backend)

При сохранении формы запускается SQL-запрос к базе данных Supabase для создания новой записи в таблице `public.users`.

*   **INSERT в `public.users`:**
    *   `role`: Устанавливается жестко в значение `'curator'`.
    *   `web_login`: Значение из формы.
    *   `web_password_hash`: **Критически важно!** Пароль, введенный в форме, **должен быть хеширован** на стороне бэкенда (например, с использованием `pg_crypto` в RPC-функции) перед сохранением в базу. Нельзя хранить пароли в открытом виде.
    *   `first_name`, `last_name`: Значения из формы.
    *   Остальные поля, связанные с Telegram (`telegram_id`, `auth_date` и т.д.), остаются `NULL`, так как куратор входит через веб-интерфейс.

**Пример RPC функции (концептуальный):**
```sql
-- public/rpc/create_curator.sql

CREATE OR REPLACE FUNCTION create_curator(
  p_first_name TEXT,
  p_last_name TEXT,
  p_web_login TEXT,
  p_password TEXT
)
RETURNS uuid
LANGUAGE plpgsql
SECURITY DEFINER
AS $$
DECLARE
  new_user_id uuid;
BEGIN
  INSERT INTO public.users (first_name, last_name, web_login, web_password_hash, role)
  VALUES (p_first_name, p_last_name, p_web_login, crypt(p_password, gen_salt('bf')), 'curator')
  RETURNING id INTO new_user_id;
  
  RETURN new_user_id;
END;
$$;
```

## 4. UI Компоненты

*   **Кнопка "Добавить куратора"**: Будет добавлена в компонент `src/pages/AdminPage/components/CuratorsManager/CuratorsManager.tsx`.
*   **Модальное окно**: Новый компонент, содержащий форму для ввода данных.
*   **Логика:** Функциональность будет добавлена в хук `useStudentsAdmin` или вынесена в отдельный хук для управления командой.

Это обеспечивает централизованное и контролируемое управление доступом для команды проекта.
