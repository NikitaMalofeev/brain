# Новая фича: Табы "Чаты", "FAQ", "Эфиры" в админ-панели

> **Статус:** Планирование  
> **Цель:** Реализовать три новых раздела в админ-ке с базовым функционалом управления контентом.

## 1. Общая концепция

Добавляем в админ-панель три новых таба:
1.  **Чаты:** Управление списком Telegram-чатов.
2.  **FAQ:** Отображение и управление часто задаваемыми вопросами.
3.  **Эфиры:** Управление списком прошедших и будущих эфиров/трансляций.

Мы начинаем с максимально простой реализации (MVP) для каждой вкладки, чтобы быстро выкатить функционал.

---

## 2. План реализации

### Шаг 1: Backend (Supabase)

#### Таблица `chats`
Простой справочник ссылок на Telegram-чаты.

**Поля:**
- `id` (uuid, PK)
- `name` (text, not null) - Название чата
- `description` (text) - Краткое описание
- `link` (text, not null) - Ссылка на чат
- `order_num` (integer) - Порядковый номер для сортировки
- `created_at` (timestamptz)

**Политики доступа (RLS):**
- **SELECT:** Все аутентифицированные пользователи.
- **INSERT, UPDATE, DELETE:** Только для роли `admin`.

#### Таблица `broadcasts` (Эфиры)
Список анонсов и записей трансляций.

**Поля:**
- `id` (uuid, PK)
- `name` (text, not null) - Название эфира
- `description` (text) - Описание
- `broadcast_url` (text) - Ссылка на трансляцию (Zoom, YouTube)
- `start_time` (timestamptz) - Дата и время начала
- `status` (text, 'planned' | 'live' | 'completed') - Статус эфира
- `recording_url` (text) - Ссылка на запись (добавляется после)
- `created_at` (timestamptz)

**Политики доступа (RLS):**
- **SELECT:** Все аутентифицированные пользователи.
- **INSERT, UPDATE, DELETE:** Только для роли `admin`.

#### Таблица `faq`
Простой справочник вопросов и ответов.

**Поля:**
- `id` (uuid, PK)
- `question` (text, not null) - Вопрос
- `answer` (text, not null) - Ответ
- `order_num` (integer) - Порядковый номер для сортировки
- `created_at` (timestamptz)

**Политики доступа (RLS):**
- **SELECT:** Все аутентифицированные пользователи.
- **INSERT, UPDATE, DELETE:** Только для роли `admin`.

### Шаг 2: Frontend (Админ-панель)

#### Обновление навигации
- Раскомментировать табы "Чаты" и "FAQ" в `src/pages/AdminPage/AdminPage.tsx`.
- Добавить новый таб "Эфиры".

#### Компонент `ChatsManager.tsx`
- **UI:** Таблица со списком чатов. Колонки: `Порядок`, `Название`, `Ссылка`, `Действия`.
- **Функционал:**
    - **Создание:** Модальное окно с полями для нового чата.
    - **Редактирование:** То же модальное окно для изменения существующего.
    - **Удаление:** Кнопка с подтверждением.
    - **Сортировка:** Простое поле `order_num` для ручного управления порядком.

#### Компонент `FaqManager.tsx`
- **UI:** Таблица со списком FAQ. Колонки: `Порядок`, `Вопрос`, `Ответ`, `Действия`.
- **Функционал:**
    - **Создание:** Модальное окно с полями для нового FAQ.
    - **Редактирование:** То же модальное окно для изменения существующего.
    - **Удаление:** Кнопка с подтверждением.
    - **Сортировка:** Простое поле `order_num` для ручного управления порядком.

#### Компонент `BroadcastsManager.tsx`
- **UI:** Таблица со списком эфиров. Колонки: `Название`, `Дата начала`, `Статус`, `Действия`.
- **Фуционал:**
    - **Создание:** Модальное окно со всеми полями из таблицы `broadcasts`.
    - **Редактирование:** То же модальное окно для обновления данных. Позволит добавить ссылку на запись после завершения эфира.
    - **Удаление:** Кнопка с подтверждением.

### Шаг 3: Хуки для работы с данными

Создадим три новых хука по аналогии с существующими (`useStagesAdmin`, `useCoursesAdmin` и т.д.).

- **`useChatsAdmin.ts`**: Будет содержать всю логику для CRUD-операций с таблицей `chats`.
- **`useFaqAdmin.ts`**: Будет содержать всю логику для CRUD-операций с таблицей `faq`.
- **`useBroadcastsAdmin.ts`**: Будет содержать всю логику для CRUD-операций с таблицей `broadcasts`.

## 3. Итог по MVP

- **Чаты:** Полный CRUD в админке.
- **FAQ:** Полный CRUD в админке.
- **Эфиры:** Полный CRUD в админке.

Такой подход позволит нам быстро реализовать базовый функционал, а в будущем, при необходимости, мы сможем усложнить систему (например, добавить категории в FAQ или привязку чатов к тарифам).

## 4. UI Спецификация (Консистентный дизайн)

### 4.1 Панель навигации
- Используем общий контейнер `.admin-tabs` для трех вкладок:
  - `<button class="admin-tab">Чаты</button>`
  - `<button class="admin-tab">FAQ</button>`
  - `<button class="admin-tab">Эфиры</button>`
- Активная вкладка имеет класс `.active` и визуальный индикатор снизу.

### 4.2 Контейнер содержимого вкладки
- Внутри каждой вкладки используется контейнер `.admin-content`.
- При переключении вкладок применяется анимация `fadeInUp` (класс `.tab-switching`).

#### 4.2.1 Чаты (ChatsManager)
- Компонент `<ChatsManager />`.
- Таблица с классом `.admin-table` и таблицей `<table>`.
- Колонки:
  1. **Перетаскивание (Drag Handle):** `<td class="drag-handle">⋮⋮</td>`
  2. **Название чата**
  3. **Описание**
  4. **Ссылка**
  5. **Действия** (редактировать / удалить)
- Реализуем drag-and-drop с помощью `react-beautiful-dnd`:
  - `<DragDropContext onDragEnd={onChatsReorder}>`
  - `<Droppable droppableId="chats">`
  - `<Draggable draggableId={chat.id} index={index}>`
  - `<tr className="draggable-row">` с `onClick` по handle для перетаскивания.

#### 4.2.2 FAQ (FaqManager)
- Компонент `<FaqManager />`.
- Таблица `.admin-table` с колонками:
  1. **Drag Handle**
  2. **Вопрос**
  3. **Ответ**
  4. **Действия**
- Используем ту же логику drag-and-drop:
  - `<DragDropContext onDragEnd={onFaqReorder}>` и соответствующие `<Droppable>`/`<Draggable>`.

#### 4.2.3 Эфиры (BroadcastsManager)
- Компонент `<BroadcastsManager />`.
- Таблица `.admin-table` с колонками:
  1. **Drag Handle**
  2. **Название**
  3. **Дата начала**
  4. **Статус**
  5. **Действия**
- Drag-and-drop для управления порядком отображения эфиров:
  - `<DragDropContext onDragEnd={onBroadcastsReorder}>`

### 4.3 Модальные окна
- Все модальные окна используют `.admin-modal-backdrop` и `.admin-modal`.
- Заголовок `<h3>` внутри модалки с визуальным маркером и кнопкой закрытия `.admin-modal-close`.
- Поля ввода используют класс `.admin-input`, кнопки — `.admin-button`.
- Валидация и подтверждение действий едины для всех менеджеров.
