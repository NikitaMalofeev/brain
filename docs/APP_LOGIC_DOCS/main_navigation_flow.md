# 🏠 Главный экран приложения (ОБНОВЛЕНО 04.06.2025)

Этот флоу описывает поведение главного экрана приложения, где пользователь видит свой основной путь обучения (ступени текущего курса) с реальными обложками из CloudFlare R2.

---

## 🧭 Что видит пользователь

Экран построен по блоку Библиотека из Figma.  
Он содержит:

- Название экрана: **«Главная»**
- **Верхний блок (шапка):**
  - Аватар пользователя (при наличии).
  - Ссылка на экран баллов, отображающая текущее количество баллов пользователя и иконку.
- Приветственный текст (опционально): например, «Выберите этап, с которого хотите продолжить» (в текущей верстке отсутствует).
- Список карточек ступеней:
  - **ОБНОВЛЕНО**: Обложки ступеней (реальные изображения из CloudFlare R2 или локальный fallback).
  - Название этапа (например, «1. Предобучение», «2. Основной блок») поверх обложки.
  - Плашка уровня (например, «LEVEL 01») поверх обложки.
  - Статус доступа: 🔒 иконка замка на плашке уровня, если этап заблокирован.
  - **НОВОЕ**: Fallback на дефолтные обложки при отсутствии `cover_image_path`.
- **Нижний блок (под списком ступеней):**
  - Информация о количестве выполненных заданий.
  - Информация о количестве заданий до следующей крупной вехи (например, ступени).
  - Иконка-стрелка, возможно, для перехода к детальной статистике.
  - Линейный прогресс-бар общего выполнения.

---

## 📦 Какие данные подгружаются (ОБНОВЛЕНО)

Из Supabase по текущему пользователю вытягиваются:

- его активное участие в курсе (`user_course_enrollments`)
- список этапов (`course_stages`) **ОБНОВЛЕНО**: включая поле `cover_image_path`
- статус открытия каждого этапа через поле `is_unlocked`
- прогресс (кол-во просмотренных материалов и сданных заданий)

**Новая структура данных ступени:**
```typescript
interface StageData {
  stage_id: number;
  stage_name: string;
  stage_description: string;
  cover_image_path?: string;  // НОВОЕ: путь к обложке в CloudFlare R2
  is_unlocked: boolean;       // ОБНОВЛЕНО: упрощенная логика через поле БД
  total_lessons: number;
  completed_lessons: number;
  order_num: number;
}
```

---

## 🔄 Как работает (ОБНОВЛЕНО)

1. **При открытии библиотеки:**
   - фронт делает запрос через функцию `get_library_stages($user_id, $course_id)`
   - **ОБНОВЛЕНО**: функция возвращает поле `cover_image_path` для обложек ступеней
   - для каждого этапа статус определяется через поле `is_unlocked` (упрощенная логика)

2. **Формируется список карточек:**
   - **НОВОЕ**: Загружаются обложки через `buildImageUrl(cover_image_path)`
   - **НОВОЕ**: При ошибке загрузки показывается дефолтная обложка
   - Открытые: можно нажать, переход к экрану этапа
   - Закрытые: замочек, кнопка неактивна

3. **При клике на открытую ступень:**
   - переход к `stage_content_flow` с `stage_id`

## 🎨 Визуальные компоненты (ОБНОВЛЕНО)

### Карточка ступени на Главном экране

В `MainPage.tsx` верстка карточки ступени осуществляется непосредственно при итерации по списку `stages`. Ключевые особенности:
- Каждая карточка является ссылкой (`<Link>`) на детальную страницу ступени (`/library/stage/:id`).
- Основа карточки — изображение (обложка), занимающее всю ее площадь.
- Поверх изображения, в левом верхнем углу, абсолютно позиционируются:
    - Название ступени (жирным шрифтом, заглавными буквами).
    - Плашка с указанием уровня (например, "LEVEL 01") и иконкой замка, если ступень не разблокирована.
- Используется фолбэк-логика для обложек: сначала попытка загрузить с CloudFlare R2, при ошибке — локальное изображение (`/stepX.png`).

```typescript
// Примерная структура элемента карточки ступени из MainPage.tsx
<Link to={`/library/stage/${stage.stage_id}`}
    className={clsx('relative bg-white/70 rounded-4xl overflow-hidden', stage.is_unlocked ? "cursor-pointer" : "pointer-events-none")}>
    <img 
      src={stage.cover_image_path ? buildImageUrl(stage.cover_image_path) : `/step${i + 1}${i + 1}.png`}
      // ... onError fallback ...
    />
    <div className={'absolute top-5 left-5 z-[2] flex flex-col gap-1'}>
        <p className={'font-bold uppercase text-black'}>{stage.stage_name}</p>
        <div className={'text-xs w-max font-medium bg-[linear-gradient(...)] px-2 py-1 rounded-full flex items-center gap-1'}>
            LEVEL 0{i + 1}
            {!stage.is_unlocked && <img src={'/lock.svg'} alt={''} />}
        </div>
    </div>
</Link>
```

Компонент `StageCard` (`src/components/StageCard/StageCard.tsx`) может использоваться на других страницах (например, `LibraryPage`), но на `MainPage` верстка карточек специфична.

## 💡 UX-детали (ОБНОВЛЕНО)

- **НОВОЕ**: Обложки ступеней придают визуальную привлекательность
- **НОВОЕ**: Система fallback для надежности отображения
- **ОБНОВЛЕНО**: Упрощенная логика разблокировки через поле `is_unlocked`
- Открытая карточка — кликабельная.
- Закрытая карточка — некликабельная, с иконкой замка на плашке уровня.
- На карточке ступени не отображается детальный прогресс "X/Y материалов", только уровень.
- Общий прогресс пользователя вынесен в отдельный блок под списком ступеней.

### 🏷️ Плашки статуса уроков

Каждая карточка урока отображает статусные плашки с приоритетом отображения:

1. **"Откроется завтра"** (высший приоритет)
   - Показывается для уроков с `open_at` = завтра (с 00:00 до 23:59)
   - Стиль: голубой градиент `bg-[linear-gradient(135deg,_rgba(141,197,241)_-48.61%,_#63ABE6_105.56%)]`
   - Цвет текста: белый
   - Логика определения: `getLessonTimeStatus(lesson)` в `LessonCard.tsx`

2. **"Завершено"** (если урок пройден)
   - Показывается для уроков с `is_completed = true`
   - Стиль: зеленый фон `bg-green-500`

3. **"Не начато"** (если урок разблокирован)
   - Показывается для доступных неначатых уроков
   - Стиль: голубой градиент (как "День N")

4. **"Заблокировано"** (если урок недоступен)
   - Показывается для заблокированных уроков
   - Стиль: серый фон `bg-gray-500`

**Техническая реализация:**
- Функция `getLessonTimeStatus()` проверяет время открытия урока
- Сравнение с завтрашним днем: от 00:00 до 23:59
- Обновлен тип `LessonData` с полем `open_at` в `useStageDetails.ts`
