# Система доступа к урокам на уровне отдельных уроков

## Обзор

Новая система позволяет управлять доступом к урокам на уровне отдельных уроков, а не по количеству уроков в тарифе. Это обеспечивает максимальную гибкость в управлении контентом.

## Архитектура

### База данных

**Новая таблица: `tariff_lesson_access`**
```sql
CREATE TABLE public.tariff_lesson_access (
  id           BIGSERIAL PRIMARY KEY,
  tariff_id    UUID NOT NULL REFERENCES public.tariffs(id) ON DELETE CASCADE,
  lesson_id    BIGINT NOT NULL REFERENCES public.lessons(id) ON DELETE CASCADE,
  created_at   TIMESTAMPTZ NOT NULL DEFAULT now(),
  UNIQUE(tariff_id, lesson_id)
);
```

**Логика доступа:**
- Если для урока **НЕТ** записей в `tariff_lesson_access` → урок доступен **ВСЕМ** тарифам
- Если для урока **ЕСТЬ** записи в `tariff_lesson_access` → урок доступен **ТОЛЬКО** указанным тарифам

### Функции

**`can_user_access_lesson(user_id, lesson_id)`**
- Проверяет доступ пользователя к конкретному уроку
- Учитывает активный тариф пользователя
- Проверяет ограничения по тарифам для урока

**`get_user_accessible_lessons(user_id, stage_id)`**
- Возвращает все уроки этапа с информацией о доступности
- Используется в `useStageDetails` для получения данных

**`get_lesson_accessible_tariffs(lesson_id)`**
- Возвращает список тарифов, имеющих доступ к уроку
- Используется в админке для отображения настроек

## Оптимизация производительности

### Проблема старой системы

В старой системе для каждого урока вызывалась отдельная функция `can_user_access_lesson()`, что приводило к N+1 запросам:

```sql
-- Для каждого урока отдельный запрос
SELECT can_user_access_lesson(user_id, lesson_1_id);
SELECT can_user_access_lesson(user_id, lesson_2_id);
SELECT can_user_access_lesson(user_id, lesson_3_id);
-- ... и так далее
```

### Новые оптимизированные функции

**`get_user_accessible_lessons_optimized(user_id, stage_id)`**
- Получает все уроки этапа за один запрос
- Проверяет доступ для всех уроков внутри SQL
- Возвращает готовые данные с флагом `is_accessible`

**`get_library_stages_optimized(user_id, course_id)`**
- Получает все этапы курса за один запрос
- Оптимизированная проверка доступа к этапам
- Убрана логика с `max_days_access`

### Преимущества оптимизации

1. **Скорость:** Вместо N+1 запросов - один запрос для всех уроков
2. **Эффективность:** Вся логика проверки доступа выполняется в SQL
3. **Масштабируемость:** Производительность не падает с ростом количества уроков
4. **Простота:** Фронтенд получает готовые данные

### Сравнение производительности

**Старая система:**
```
Запрос 1: get_library_stages() - 1 запрос
Запрос 2: can_user_access_lesson() для урока 1 - 1 запрос
Запрос 3: can_user_access_lesson() для урока 2 - 1 запрос
...
Запрос N+1: can_user_access_lesson() для урока N - 1 запрос
Итого: N+1 запросов
```

**Новая оптимизированная система:**
```
Запрос 1: get_library_stages_optimized() - 1 запрос
Запрос 2: get_user_accessible_lessons_optimized() - 1 запрос
Итого: 2 запроса
```

## Логика работы

### 1. Проверка доступа к уроку

```typescript
// В useStageDetails.ts
const isLessonAccessible = (lesson, isAccessibleByTariff) => {
    // 1. Проверка временного ограничения
    const now = new Date();
    const openAt = lesson.open_at ? new Date(lesson.open_at) : null;
    if (openAt && now < openAt) return false;

    // 2. Проверка доступа по тарифу
    return isAccessibleByTariff;
};
```

### 2. Получение данных уроков (ОПТИМИЗИРОВАННО)

```typescript
// Получаем уроки с информацией о доступности за один запрос
const { data: lessonsWithAccess } = await supabase
    .rpc('get_user_accessible_lessons_optimized', {
        p_user_id: user.id,
        p_stage_id: stageId
    });
```

### 3. Отображение в UI

- **Доступные уроки:** Отображаются нормально, можно кликать
- **Недоступные уроки:** Иконка замка, клик заблокирован
- **Статусы:** "Заблокировано", "Откроется завтра", "Доступно"

## Админка

### Управление доступом

1. **Открытие модального окна:** Кнопка "Доступ" в списке уроков
2. **Выбор тарифов:** Чекбоксы для каждого тарифа
3. **Сохранение:** Кнопка "Сохранить" обновляет `tariff_lesson_access`
4. **Логика:** Пустой список = доступ всем, выбранные тарифы = ограниченный доступ

### Интерфейс

```
Доступ к уроку: "Название урока"

Доступные тарифы:
☑️ Тариф 250+ (T1)
☑️ Тариф 500+ (T2)
☐ Тариф 1млн+ (T3)
☐ Тариф 10млн+ (T4)

💡 Если ни один тариф не выбран, урок будет доступен всем тарифам
📋 Выберите конкретные тарифы для ограничения доступа к уроку

[Сохранить] [Отмена]
```

## Миграция с старой системы

### Что изменилось

1. **Убрана логика `max_days_access`** из `tariff_limits`
2. **Убрано поле `lessons_available_by_tariff`** из `get_library_stages`
3. **Добавлена таблица `tariff_lesson_access`** для гранулярного управления
4. **Обновлены функции** для работы с новой логикой
5. **Добавлены оптимизированные функции** для улучшения производительности

### Совместимость

- **Существующие данные:** Не затронуты
- **Старые ограничения:** Можно удалить через админку
- **Новые уроки:** По умолчанию доступны всем тарифам
- **Старые функции:** Остаются для обратной совместимости

## Преимущества новой системы

1. **Гибкость:** Можно ограничить доступ к любому уроку в любом месте курса
2. **Простота:** Понятная логика "есть запись = ограничение, нет записи = доступ всем"
3. **Масштабируемость:** Легко добавлять новые тарифы и уроки
4. **UX:** Пользователь видит все уроки, но недоступные заблокированы
5. **Админка:** Удобное управление через чекбоксы
6. **Производительность:** Оптимизированные запросы вместо N+1

## Примеры использования

### Ограничение доступа к премиум-уроку

```sql
-- Урок доступен только тарифам T3 и T4
INSERT INTO tariff_lesson_access (tariff_id, lesson_id) VALUES
('33333333-3333-3333-3333-333333333333', 15), -- T3
('44444444-4444-4444-4444-444444444444', 15); -- T4
```

### Урок для всех тарифов

```sql
-- Никаких записей в tariff_lesson_access = доступ всем
-- Удаляем все записи для урока 10
DELETE FROM tariff_lesson_access WHERE lesson_id = 10;
```

### Специальный урок для одного тарифа

```sql
-- Урок доступен только тарифу T1
INSERT INTO tariff_lesson_access (tariff_id, lesson_id) VALUES
('11111111-1111-1111-1111-111111111111', 20); -- T1
```
