# Требования к реализации фичи "Тарифы"

Этот документ описывает технические требования для разработки фронтенд-части функционала тарифов в административной панели и пользовательском приложении.

---

## Этап 1: Матрица Доступа по Тарифам

Здесь зафиксированы правила доступа, которые должны быть реализованы в системе.

- **Тариф "250+" (T1):**
    - **Предобучение:** Полный доступ.
    - **Основное обучение:** Доступ к первым **7 дням** (урокам).
    - **Уровень "Доктор наук":** Условный доступ (только после сдачи всех ДЗ на предыдущих этапах).
    - **Уровень "Спецслужбы":** Условный доступ (только после сдачи всех ДЗ на предыдущих этапах).
    - **Доп. материалы и чаты:** Доступ определяется вручную в админ-панели.

- **Тариф "500+" (T2):**
    - **Предобучение:** Полный доступ.
    - **Основное обучение:** Доступ к первым **9 дням** (урокам).
    - **Уровень "Доктор наук":** Условный доступ (только после сдачи всех ДЗ на предыдущих этапах).
    - **Уровень "Спецслужбы":** Условный доступ (только после сдачи всех ДЗ на предыдущих этапах).

- **Тариф "1млн+" (T3):**

    - **Основное обучение:** Полный доступ (**все 12 дней**).
    - **Уровень "Доктор наук":** Полный безусловный доступ.
    - **Уровень "Спецслужбы":** Полный безусловный доступ.
    - **Доп. материалы и чаты:** Доступ определяется вручную в админ-панели.

- **Тариф "10млн+" (T4):**
    - **Предобучение:** Полный доступ.
    - **Основное обучение:** Полный доступ (**все 12 дней**).
    - **Уровень "Доктор наук":** Полный безусловный доступ.
    - **Уровень "Спецслужбы":** Полный безусловный доступ.

## Этап 3: Требования к Административной панели

### 1. Управление Тарифами (CRUD)

- **Где:** Создать новый раздел в админ-панели под названием "Тарифы".
- **Что:** Этот раздел должен отображать таблицу со всеми тарифами из `public.tariffs`.
- **Колонки:** `Название`, `Код`, `Описание`.
- **Действия:** Добавить возможность создавать, редактировать и (опционально) удалять тарифы. Эта функциональность нужна для гибкости в будущем.

#### UI Требования
- Использовать тот же компонент таблицы (`<Table>`) и модалки (`<ModalForm>`) как в разделах "Чаты", "FAQ", "Эфиры".
- В шапке таблицы разместить кнопку "Создать тариф" (primary), открывающую форму создания.
- В каждой строке таблицы добавить иконки "Редактировать" и "Удалить" (при наведении) по образцу остальных разделов.
- Форма создания/редактирования должна содержать поля:
  - `Название` (TextInput)
  - `Код` (TextInput)
  - `Описание` (Textarea)
- На форме предусмотреть валидацию: `Название` и `Код` обязательны.

### 2. Назначение Тарифа Пользователю

- **Где:** В существующем разделе управления студентами (`StudentsManager`), в карточке детального просмотра конкретного пользователя.
- **Что:** Добавить выпадающий список (select) с меткой "Текущий тариф".
- **Логика:**
    - Список должен подгружать названия всех тарифов из `public.tariffs`.
    - При выборе тарифа и сохранении, система должна создать/обновить запись в `public.user_tariffs`, связав `user_id` с `tariff_id` и установив `is_active = true`.
    - Если у пользователя уже был другой активный тариф, его запись должна получить `is_active = false`.

#### UI Требования
- В карточке пользователя под блоком "Роль" добавить строку "Текущий тариф".
- Использовать тот же `<Select>` компонент, что и для выбора роли или статуса, со списком тарифов.
- После выбора тарифа и клика по кнопке "Сохранить" (или аналогичной) форма должна отправляться через API, результат отображать в тосте.
- Если тариф назначен успешно, обновить отображение рядом с полем "Текущий тариф".

### 3. Настройка Лимитов для Этапов Курса

- **Где:** В разделе управления этапами курсов (`StagesManager`), при редактировании конкретного этапа.
- **Что:** Добавить новую секцию "Доступ по тарифам".
- **Логика:**
    - В этой секции должен отображаться список всех тарифов.
    - Напротив каждого тарифа должно быть два полей:
        1.  **"Макс. дней/уроков доступа"**: числовое поле для `tariff_limits.max_days_access`.
        2.  **"Требуется сдача всех ДЗ"**: чекбокс для `tariff_limits.requires_full_prereq`.
    - Сохранение этих настроек должно создавать или обновлять соответствующие записи в таблице `public.tariff_limits`.

#### UI Требования
- Разместить секцию "Доступ по тарифам" под основными полями редактирования этапа, внутри аккордеона (`<Accordion>`).
- Внутри секции использовать таблицу без пагинации:
  - Строки: тарифы
  - Колонки: `Тариф`, `Макс. дней/уроков`, `Требует сдачи ДЗ`.
- Поля в ячейках должны быть редактируемыми inline:
  - Числовой `<Input type="number">` для максимального количества дней.
  - `<Checkbox>` для условия сдачи.
- После редактирования всех полей кнопка "Сохранить настройки" расположена внизу секции.

### 4. Управление Доступом к Доп. Материалам и Чатам

- **Где:**
    - В разделе управления дополнительными материалами (`MaterialsManager`), при редактировании материала.
    - В разделе управления чатами (`ChatsManager`), при редактировании чата.
- **Что:** В формах редактирования добавить секцию "Доступно для тарифов".
- **Логика:**
    - Секция должна содержать список всех тарифов с чекбоксами напротив каждого.
    - Отметка чекбокса и сохранение должны создавать запись в `public.tariff_material_access` или `public.tariff_chat_access`.
    - Снятие отметки и сохранение должны удалять соответствующую запись.

#### UI Требования
- В форме редактирования материала/чата добавить блок "Доступно для тарифов" перед основными полями.
- Использовать компонент `<CheckboxGroup>` или набор отдельных `<Checkbox>` для каждого тарифа.
- Чекбоксы должны отображаться в одну линию или компактной сетке из столбцов в зависимости от ширины экрана.
- Кнопка "Сохранить" внизу формы должна сохранять и эту настройку вместе с остальными полями.

## Этап 4: Требования к Пользовательскому приложению

- [ ] Применить миграции для разграничения доступа к материалам и чатам на фронте

### 1. Библиотека (`LibraryPage`) и Карточки Этапов (`StageCard`)

- **Хук `useLibraryStages`:** Мы уже обновили его в миграции. Он теперь возвращает `lessons_available_by_tariff`.
- **Список Уроков:**
    - При клике на карточку этапа, в списке уроков должны открываться только те уроки, которые доступны по тарифу (например, первые 7 уроков для тарифа T1, если `max_days_access = 7`), но отображаться все уроки, которые есть на этом этапе.

### 2. Доступ к Дополнительным Материалам и Чатам

- **Получение данных:**
    - Хук, загружающий список доп. материалов, должен быть изменен. Он должен запрашивать у бэкенда только те материалы, которые доступны для текущего тарифа пользователя (на основе записей в `tariff_material_access`).
    - Аналогично для хука, загружающего список чатов (на основе `tariff_chat_access`).
- **UI:** Никаких изменений не требуется, страницы просто будут отображать отфильтрованный список.
