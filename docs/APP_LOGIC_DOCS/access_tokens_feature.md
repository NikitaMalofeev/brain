### 🚀 Что делаем дальше — фин-план по токенам

> TL;DR: Добавляем таблицу `access_tokens`, атомарно активируем её через Edge-функцию, даём админам batch-генерацию и копирование ссылки формата
> `https://t.me/<bot>?startapp=<token>`.
> Мигрируем существующих участников напрямую в `user_course_enrollments`, без токенов.

---

## 1. Схема данных

```sql
create table access_tokens (
    id                   uuid primary key default gen_random_uuid(),
    token                text not null,                -- base62, 16 симв.
    course_id            uuid references courses(id),
    tariff_id            uuid references tariffs(id),  -- тариф ± 1 поток сейчас
    status               text not null default 'created' check (status in ('created','used')),
    used_by_user_id      uuid references users(id),
    used_at              timestamptz,
    created_by_user_id   uuid references users(id),
    comment              text,
    created_at           timestamptz default now()
);
create unique index access_tokens_token_uidx on access_tokens(token);
```

*Таблицы `tariffs`, `courses`, `users` и `user_course_enrollments` уже описаны в PRD* .

---

## 2. Поток активации

1. **Админ** генерит токен/пакет токенов и сразу копирует ссылку вида

   ```
   https://t.me/OUR_BOT?startapp=<token>
   ```
2. **Покупатель** кликает эту ссылку — Telegram сразу открывает Mini-App (без лишних нажатий).
3. В Mini-App через `WebApp.initData` получаем токен, вызываем RPC-функцию:

   * проверяем `access_tokens` (`status='created'`);
   * в транзакции делаем `UPDATE … status='used', used_by_user_id=?, used_at=now()`;
   * пишем запись в `user_course_enrollments` + `tariff_id` в `profiles`.


---

## 2.1. Обработка ошибок в Mini-App

В случае, если токен невалиден (не найден, уже использован, истёк срок и т.д.), Mini-App должно показать пользователю отдельную страницу с информацией:
*   **Заголовок:** "Ошибка активации"
*   **Текст:** "К сожалению, этот код доступа недействителен. Пожалуйста, проверьте правильность ссылки или обратитесь в поддержку."
*   **Кнопка:** "Написать в поддержку" (ведёт на Telegram-чат поддержки).

## 3. Генерация токена

* **Формат.** `base62(16)` ≈ 95 бит энтропии, короче 64-символьного лимита Telegram.
* **Храним в plain-text.** Хеш не нужен (нет повторного использования, RLS ограничит SELECT).
* **Batch.** Запрос принимает `count` + `tariff_id`; возвращает массив строк-ссылок.

## 5. Безопасность & RLS

```sql
-- Только сервис-роль и роли 'admin'/'curator' могут INSERT/SELECT/UPDATE
create policy "tok_admin" on access_tokens
  for all using (auth.role() in ('service_role','admin','curator'));
-- Обычному участнику SELECT запрещён.
```

---

## 6. Telegram-бот (Фолбэк-механизм)

* `/start <token>` обработчик (является второстепенным, основной флоу - через `startapp`):

  * проверяет формат токена (16-char base62);
  * делает быстрый вызов RPC-функции через Supabase, получает результат `{ok|error}`;
  * шлёт кнопку `web_app` (token в URL) или сообщение об ошибке («токен недействителен / уже использован»).
* **Inline-mode** не нужен.

## 7. Миграция существующих участников

```sql
insert into user_course_enrollments (user_id, course_id, enrollment_date, status)
select u.id, <course_id>, now(), 'active'
from profiles u
where u.tariff_id is not null;
```

Токены им **не** создаём; Mini-App пустит их по уже прописанному `tariff_id`.

## 8. Текущее состояние реализации (Январь 2025)

### ✅ Что УЖЕ реализовано:

**Frontend (Mini-App):**
- **Проверка токена из startParam** - при запуске приложения извлекается токен из Telegram launch параметров
- **Логика обработки токена** - вызов RPC функции `redeem_access_token` с токеном
- **Проверка активного тарифа** - через хук `useActiveTariff` проверяется наличие активного тарифа у пользователя
- **Контроль доступа**: 
  - Если нет активного тарифа И нет токена → показ `TokenErrorPage`
  - Если есть токен → попытка активации, при ошибке → показ `TokenErrorPage` с деталями ошибки
  - Если есть активный тариф → доступ к приложению
- **Обработка ошибок** - показ `TokenErrorPage` с сообщением об ошибке и кнопкой "Написать в поддержку"
- **Инвалидация кэша** - после успешной активации токена обновляется информация о пользователе и тарифах

**Admin Panel (Генерация токенов):**
- **Интерфейс создания токенов** - форма с выбором курса, тарифа и количества токенов
- **Конфигурация бота** - название бота подтягивается из `BOT_CONFIG.BOT_NAME` (env: `VITE_TELEGRAM_BOT_NAME`)
- **Копирование ссылок** - генерация и копирование ссылок формата `https://t.me/{BOT_NAME}?startapp={token}`
- **Хуки для админки** - `useTokensAdmin`, `useCoursesAdmin`, `useTariffsAdmin`

### ✅ Что ТАКЖЕ УЖЕ реализовано (Backend):

**Database:**
- **Таблица `access_tokens`** - СУЩЕСТВУЕТ! Полная структура с полями: id, token, course_id, tariff_id, status, used_by_user_id, used_at, created_by_user_id, comment, created_at
- **RPC функция `redeem_access_token`** - СУЩЕСТВУЕТ! Принимает `token_to_redeem text`, возвращает JSON
- **Таблица `user_tariffs`** - СУЩЕСТВУЕТ! Связь пользователей с тарифами
- **Таблица `tariffs`** - СУЩЕСТВУЕТ! Справочник тарифов (T1, T2, T3, T4)
- **Таблица `courses`** - СУЩЕСТВУЕТ! Курсы для токенов
