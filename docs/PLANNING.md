# План проекта "Brain Programming"

## 1. Введение

*   **Backend:** Supabase (PostgreSQL, Auth, Storage, Functions)
*   **Frontend:** React (TypeScript, Vite)
*   **Telegram Mini App SDK**

## 2. Основные цели

*   Создание образовательной платформы для Telegram.
*   Интерактивное обучение с геймификацией.
*   Административная панель для управления контентом и пользователями.

## 3. Архитектура

*   **Frontend:** React (TypeScript) с использованием Vite.
*   **Backend:** Python (FastAPI / Flask - выбрать или уточнить) или Node.js (Express - выбрать или уточнить). Пока что логика на клиенте, бекенда как такового нет, используется Supabase.
*   **База данных:** Supabase (PostgreSQL).
*   **Аутентификация:** Supabase Auth.
*   **Файловое хранилище:** Cloudflare R2.
*   **Развертывание:** Vercel (Frontend), Railway (Backend - если будет).

## 5. Стиль Кода и Соглашения

*   **Общие:**
    *   Чистый, читаемый, поддерживаемый код (SOLID, DRY, KISS).
    *   Модульность: файлы не более 300 строк, логические модули/компоненты.
    *   Относительные импорты внутри пакетов/модулей.
    *   Комментарии на русском языке для нетривиальных участков кода.
*   **TypeScript/React:**
    *   Стандарты сообщества.
    *   Prettier для форматирования.
    *   ESLint для линтинга.
    *   Функциональные компоненты с использованием хуков.
    *   Именование: `PascalCase` для компонентов, `camelCase` для переменных и функций.
*   **Python (если будет):**
    *   PEP 8.
    *   Type hints.

## 6. Ограничения

*   Соблюдение лимита в 300 строк на файл.
*   Регулярные коммиты с осмысленными сообщениями.
*   Обновление `TASK.md` при начале и завершении задач.

## 7. Структура Проекта (Примерная)

См. актуальную структуру в `project_layout`. Основные директории:

*   `src/`: Исходный код фронтенда.
    *   `components/`: Общие компоненты React.
    *   `pages/`: Компоненты страниц.
    *   `lib/`: Вспомогательные функции, API клиенты (Supabase, R2).
    *   `contexts/`: React contexts.
    *   `assets/`: Статические ассеты.
    *   `styles/`: Глобальные стили.
*   `api/` (если будет): Исходный код бэкенда.
*   `docs/`: Документация.
    *   `APP_LOGIC_DOCS/`: Документация по бизнес-логике.
*   `public/`: Статические файлы, доступные из корня сайта.

## 8. Процесс Разработки

1.  **Задача:** Берется из `TASK.md` или создается новая.
2.  **Планирование:** Определяются шаги для выполнения задачи (добавляются в `TASK.md`).
3.  **Разработка:** Написание кода согласно плану и стандартам.
4.  **Тестирование:** Локальное тестирование функционала.
5.  **Коммит:** Фиксация изменений в Git.
6.  **Обновление `TASK.md`:** Отметка о выполнении задачи.
7.  **Push:** Отправка изменений на GitHub.
8.  **Деплой:** Автоматический деплой через Vercel/Railway при пуше в основную ветку.
